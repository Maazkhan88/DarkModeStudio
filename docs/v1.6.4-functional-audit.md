# Dark Mode Studio — v1.6.4 Functional Audit

**Date**: 2026-08-31  
**Target Release**: v1.6.4  
**Auditor**: Antigravity (QA Engineer + Secondary Developer)  

---

## 1. Database Upgrades & Schema Lineage

- **Historical v4 Schema**: Preserved as immutable artifact in `app/schemas/com.darkmodestudio.commandcenter.core.database.DmsDatabase/4.json` (identity hash `81b343b1d29f50ae51d109db735fd323`).
- **Current v5 Schema**: Bumped `@Database(version = 5)` and exported `5.json` (identity hash `a00c511a492ec6dfe365e990325a57e6`).
- **Migration Path 4 $\rightarrow$ 5**:
  - Adds `repositoryDefaultBranch` column to `projects`.
  - Creates composite index `index_tasks_projectId_status` on `tasks(projectId, status)`.
  - Drops redundant single-column index `index_tasks_projectId`.
  - Migrates `repository_file_entries` to branch-scoped schema with index on `(repositoryFullName, branch, path)`.
- **Validation**: Verified using `androidx.room.testing.MigrationTestHelper` in `RoomMigrationTest.kt`. Data across all entities is verified intact post-migration.

---

## 2. GitHub Imports vs Project Planning State

- **Truthful Status**: Newly imported GitHub repositories are assigned `ProjectStatus.IMPORTED` (`"Imported"`, hollow node style).
- **Phase Weights**: Initialized with `0f` (unconfigured), avoiding synthetic 15/45/20/20 progress claims.
- **Milestones**: Initialized as empty; displayed as `"No milestones defined"`.
- **Preservation of Local State**: If a repository was already planned in DMS, synchronization updates only GitHub telemetry (`pushed_at`, commits, PRs, workflows, default branch) while retaining user-defined status, due dates, milestones, task progress, and phase weights.

---

## 3. Repository Files Cache & Branch Scoping

- **Cache Keys**: Format is `${repositoryFullName}:${branch}:${path}:${name}`.
- **DAO Queries**: Scope all selections and deletions by `(repositoryFullName, branch, path)`.
- **Branch Coexistence**: Validated in `RepositoryFilesRepositoryTest.kt` that cache entries for `main` and `develop` branches coexist without cross-branch contamination.
- **Unlinked State**: Projects without a linked GitHub repository correctly report `RepositoryFilesState.NotLinked` with clear action prompts in UI.

---

## 4. Legacy Database Fileset Migration

- **All-or-Safe Semantics**: Treats `dark_mode_studio.db`, `dark_mode_studio.db-wal`, and `dark_mode_studio.db-shm` as an atomic migration unit.
- **Copy & Verify**: Copies files to destination and validates size and file existence before deleting legacy files.
- **Failure Handling**: Any copy or validation failure safely cleans up partial targets and preserves legacy files intact.
- **Tested Scenarios**: Full fileset migration, standalone DB without WAL/SHM, destination already exists, and non-existent legacy sources.

---

## 5. Security & Build Audit

- **Credentials**: Stored in Android Keystore using AES-GCM; UI copy accurately describes Keystore encryption without hardware enclave over-claims.
- **Secrets Audit**: 0 hardcoded GitHub tokens (`ghp_`, `github_pat_`) or byte array credential reconstructions in production code.
- **Dead Code**: `LiveCloudHub.kt` completely removed.
- **CI**: Automated GitHub Actions verification in `.github/workflows/android-verify.yml`.
